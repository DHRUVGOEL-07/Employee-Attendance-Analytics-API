# REVIEW.md

Defects found in the starter `app/main.py`, with where, what, how to notice, and the fix.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `punch_in` (date), `create_employee` (`created_at`) | `datetime.fromtimestamp(ms/1000)` and `datetime.now()` use the **server's local zone**, not IST, so `date` is wrong (R1). `created_at` is a naive local time. | Server in UTC, punch-in at 00:30 IST on 7 Jul: `date` comes back `2026-07-06`. | `ms_to_dt` builds a UTC-aware datetime; the attendance date comes from `shift_window`, which converts to IST. `created_at` is `datetime.now(UTC)`. |
| 2 | `compute_late_minutes` | Takes the shift start on the **punch-in's own calendar date** (UTC/naive), so overnight shifts and IST/UTC boundaries break. Uses `int(x/60)` then `> 10`, so 09:40:01 gives 0 (R2 says 10) and a punch-in 09:40:59 also gives 0. | 09:40:01 on a 09:30 shift returns 0 instead of 10. Overnight shift 22:00 punch-in at 03:00 gets a negative or huge value. | Takes the real shift-start instant from `shift_window`. Late iff `seconds > 600`, then `seconds // 60`. |
| 3 | `compute_work_hours` | `round()` is banker's rounding on a float; R4 wants exact half-up. No second truncation. | 9630 s = 2.675 h: `round(9630/3600, 2)` gives 2.67 (float is 2.67499...), R4 half-up says 2.68. | `Decimal(secs) / 3600` quantized with `ROUND_HALF_UP`. Instants are truncated to whole seconds on entry. |
| 4 | `compute_overtime` | Uses the record date as the shift-end day (wrong for overnight). Mixes an aware `end` with naive `punch_out` (`TypeError`). No 30-minute minimum, so 5 min counts (R3). Result is not floored by the threshold. | Punch-out 18:35 on a 18:30 shift returns 5, expected 0. Overnight 22:00-06:00 shift, punch-out 06:30 next day: the end is taken as 06:00 on the *record* date, so overtime comes out ~1470 min instead of 30. | Takes the real shift-end instant from `shift_window` (next day for overnight); `minutes = secs // 60`, counted only if `>= 30`. |
| 5 | `punch_in` | `emp` is never checked, so an unknown `emp_code` gives `TypeError` on `emp["shift_start"]`, i.e. a **500** instead of 404. | `POST /attendance/punch-in {"emp_code": "NOPE"}`. | Explicit 404. |
| 6 | `punch_in` (race) | Check-then-insert: two simultaneous requests both pass `find_one` and both insert, so two records for one (emp_code, date). No unique index exists. | Fire 10 parallel punch-ins: more than one 201. | Unique index on `(emp_code, date)` created at startup; insert, and map `DuplicateKeyError` to 409. |
| 7 | `create_employee` (race) | Same check-then-insert pattern for `emp_code`; there is no unique index. | Parallel duplicate creates yield several 201s. | Unique index on `emp_code`; `DuplicateKeyError` becomes 409. |
| 8 | `PunchInIn`, `EmployeeIn` (validation) | No validation: `status` is any string (`ABSENT`, `foo` accepted); `punched_at` accepts seconds, floats, `True`; `0` is falsy so it silently means "now"; `emp_code`, email, `HH:MM`, `joined_on` are unchecked; `shift_start == shift_end` allowed. All should be 422. | `punched_at: 1783312500` (seconds), `status: "ABSENT"`, `joined_on: "2026-02-30"`, `shift_start: "25:99"`. | Strict pydantic types: `StrictInt` bounded to the contract's ms range, `Literal` for presence statuses, regex plus real calendar-date check, a model validator for equal shifts, `EMP\d{4,6}` pattern. `is not None` instead of truthiness. |
| 9 | `list_employees` (pagination) | `skip = page * page_size` skips the whole first page (off by one). | `page=1` returns the second page. | `(page - 1) * page_size`. |
| 10 | `list_employees` (total, sort, bounds) | `total` counts the whole collection, ignoring `department`. No sort, so order is not by `emp_code`. `page=0`, `page_size=100000` or negatives are accepted. | `?department=Ops` returns 3 items but total 7. | `count_documents(q)` with the same filter; `.sort("emp_code")`; `Query(ge=1)` and `page_size <= 100`. |
| 11 | `list_attendance` (scale) | `find(q)` loads every matching document into memory, sorts in Python, and slices. 100k records per request. No indexes. | Latency and memory grow with the collection; explain shows COLLSCAN. | Server-side `sort`/`skip`/`limit` plus `count_documents`, backed by compound indexes `(date desc, emp_code)`, `(status, date desc, emp_code)` and the unique `(emp_code, date)`. |
| 12 | `list_attendance` (contract) | Sort is date desc only, so ties are unordered (should be emp_code asc). `date_from > date_to`, malformed dates and unknown `status` are not rejected. Leaks an `id` (= `_id`) and returns raw datetimes instead of epoch ms. | `?date_from=2026-13-45` is accepted; response has `"id"`. | Sort `(date desc, emp_code asc)`; dates validated; `status` is a `Literal`; `date_from > date_to` returns 422; `serialize_attendance` drops `_id` and converts to epoch ms. |
| 13 | `punch_in` (response) | Returns `id` (`_id`) and raw datetime objects. `_id` is never meant to be exposed; instants must be epoch ms. Seconds are not truncated. | Response contains `"id"` and ISO datetime strings. | `serialize_attendance`; `punch_in` is truncated to whole seconds before computing and storing. |
| 14 | `create_employee` (response) | Returns the document after `insert_one` mutated it with `_id` (popped), but `created_at` is a datetime, not epoch ms. | `created_at` is an ISO string. | `serialize_employee`. |
| 15 | `/health` | Always returns `ok`, even when MongoDB is down; the contract wants 503. | Stop MongoDB, `GET /health` still 200. | `client.admin.command("ping")`; any `PyMongoError` returns 503. |
| 16 | Client setup (tz handling) | `MongoClient` default returns **naive** datetimes. Any comparison with aware values raises `TypeError`, and naive-as-local is silently wrong. | First time a stored datetime is read and subtracted from an aware one. | `tz_aware=True, tzinfo=UTC`; `dt_to_ms` also tolerates naive values. |
| 17 | Startup | No indexes at all, so every query is a COLLSCAN and uniqueness is not enforced. | Explain output. | `ensure_indexes()` at startup (idempotent), retried from `/health` if Mongo was not up yet. A short `serverSelectionTimeoutMS` so `/health` returns quickly. |

## Looked at and decided to leave

- `load_dotenv()` with default `override=False`: real environment variables already win over `.env`, as the contract requires.
- Plain `def` endpoints with the synchronous PyMongo client: FastAPI runs them in a thread pool, so concurrent requests do not block the event loop. Safe because correctness comes from unique indexes, not from in-process locks.
- Default fallback `mongodb://localhost:27017` / `attendance_db`: only used when the variables are unset, so the grader's injected values always win. Not a hard-coded connection.
- `history: []` on new records: correct. Punch-in never writes to history.
